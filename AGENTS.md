# Project language policy

English is the default language for project artifacts, including code identifiers,
comments, docstrings, user interface text, errors, logs, configuration examples,
tests, documentation, evaluation reports, and demonstration materials.

Use another language only when required for source fidelity, an external
requirement, or a specific product-owner instruction. Preserve original quotations,
official names, and existing source documents where necessary; explain material
exceptions in English. Do not translate quoted evidence in a way that replaces
or obscures its original wording.

Direct collaboration with the product owner may follow the language of their
messages. This does not change the default language of project deliverables.
